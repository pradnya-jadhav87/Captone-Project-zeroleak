## 2. Deep Technical Breakdown of Core Modules

### 2.1 AI University Examination Generator (`server/aiExamBridge.ts`, `server/aiExamGenerator.py`)
- **Problem Solved:** Manual university question paper preparation is slow, prone to bias, leaks, formatting inconsistencies, and invalid mathematical mark schemes.
- **Implementation:** The system takes uploaded syllabus files, past examination papers, or manual prompts, analyzes the structural blueprint (Section I/II, Question counts, compulsory rules, marks brackets `[14 Marks]`), and synthesizes syllabus-compliant questions.
- **LaTeX Compilation Engine:** Invokes the standalone **Tectonic** executable (`bin/tectonic.exe`) to compile raw TeX directly into vectorized, watermarked PDFs in ~0.75 seconds without needing a full 5GB TeXLive distribution.
- **Zero-Download Protection:** Raw download buttons have been removed. Instead, the paper must be dispatched directly to a certified Printing Operator (`role = 'CENTRE_OPERATOR'`) at an approved examination centre, logging the transfer into the custody ledger.

### 2.2 Threshold Encryption & Key Management (`server/thresholdKeyService.ts`)
- **Problem Solved:** Single-administrator vulnerability where one malicious or compromised user can steal decryption keys.
- **Mathematical Basis:** Implements Shamir's Secret Sharing over the finite Galois Field $GF(2^8) = GF(256)$ using the irreducible polynomial $P(x) = x^8 + x^4 + x^3 + x + 1$ ($0x11b$ in hexadecimal).
- **Threshold Policy:** Evaluates a $(2, 3)$ threshold scheme where 3 shares are minted:
  - Share 1: Organization Owner (`ORG_OWNER`)
  - Share 2: Examination Manager (`EXAM_MANAGER`)
  - Share 3: Security Auditor (`AUDITOR`)
- **Reconstruction:** Lagrange polynomial interpolation requires at least 2 distinct custodian shares to reconstruct the 256-bit AES Data Encryption Key. Any single share provides mathematically zero information about the secret.

### 2.3 Time-Locked Delivery & Enclave Printing (`server/printStation.ts`, `server/competitiveExam.ts`)
- **Problem Solved:** Leaks that occur when question papers are distributed hours or days in advance to exam centres.
- **Implementation:** The backend evaluates the server monotonic clock against `exam_date` and `unlock_time`. Before the unlock window, all paper payloads returned by APIs have their question text and decryption keys strictly redacted.
- **Secure Print Relay:** When unlocked, the Centre Operator opens an ephemeral Wi-Fi Print Relay broadcasting discovery beacons over UDP port 45412. Secondary printing terminals pair using a 6-digit crypto-random pairing code and must be admitted by the operator. Each printed sheet receives a unique, serialized serial number tracked in `print_copies`.

### 2.4 Deep Learning Proctoring & Surveillance (`security_monitor.py`, `server/proctor.ts`)
- **Problem Solved:** Remote candidate malpractice during paper drafting, verification, or candidate examinations.
- **Model:** Ultralytics YOLOv8 Nano (`yolov8n.pt`) deep learning model running inference on live webcam and RTSP streams.
- **Detection Classes:**
  - Class 0: `person` (flags missing candidate or multiple unauthorized individuals).
  - Class 67: `cell phone` (flags mobile device presence).
- **Temporal Debouncing:** Requires 3 consecutive frames of cell phone detection before locking a violation to eliminate transient false positives. Dispatches violation events to the database and raises the candidate's penalty score.
